# Google Business Profile API 連携 設計メモ（検討）

> 目的：店舗のGoogleマップ上の**実際の口コミ（件数・平均★・本文・返信）を定期取得**し、ダッシュボードで可視化・推移管理する。
> 位置づけ：[企画書](企画書.md) 第6章③（業種ベンチマークの土台）/ [機能要件](機能要件.md) 次フェーズ。
> 前提：本機能は**外部依存と審査**があり、価値検証（E1/E2）と並行 or その後に着手する想定。

---

## 1. これで何が取れるか

Google Business Profile API の `accounts.locations.reviews` で、**自店（管理権限のあるロケーション）**の口コミを取得できる：

- 口コミ1件ごと：星評価・本文・投稿者名・投稿日時・オーナー返信
- 集計：総口コミ数、平均★（API側で `averageRating` / `totalReviewCount` 取得可）

→ ダッシュボードで「**Google上の総口コミ数・平均★・推移**」を表示し、ツールの「Google誘導数」と対比できる（誘導→実投稿の歩留まりが見える）。

## 2. 前提・ハードル（正直に）

| 項目 | 内容 | 難度 |
|---|---|---|
| API利用申請 | Business Profile APIは**申請制**。Googleの承認が必要（数日〜数週間、却下もあり得る） | 高 |
| OAuth認可 | 各店舗オーナーが**自分のGoogleビジネスプロフィールへのアクセスを認可**する必要（または当社をロケーション管理者に招待） | 中 |
| スコープ審査 | `business.manage` は**機微スコープ**。本番公開には**OAuthアプリ検証**（プライバシーポリシー・ドメイン確認等、場合によりセキュリティ評価）が必要 | 高 |
| 手軽さとの矛盾 | オーナーにOAuth操作を求める＝「設定が数分」という売りと相反する | 中 |
| クォータ | 取得回数に上限。cronは1日数回程度に | 低 |

> ⚠️ 「レビューURLを設定するだけ」では取得できない（あれは投稿への一方向リンク）。**読み取りには上記のAPI＋認可が必須**。

## 3. 認証・取得フロー（設計）

1. 当社でGoogle Cloudプロジェクト作成 → Business Profile API有効化 → **利用申請**
2. OAuth 2.0 クライアント作成（リダイレクトURIは本番ドメイン）
3. 店舗オーナーが管理画面から「Google連携」→ Googleログイン＆**認可**（scope: `business.manage`）
4. アクセストークン＋**リフレッシュトークンをDBに暗号化保存**
5. **cron（コアサーバーV2）**で定期的に `accounts.locations.reviews` を取得（トークンは自動更新）
6. 取得した口コミをDB保存 → ダッシュボード表示・推移グラフ

代替：APIを使わず**当社アカウントを各店のロケーション管理者に招待**してもらう運用もあるが、いずれにせよAPI申請＋OAuthは必要。

## 4. データモデル（追加予定）

```
google_credentials(business_id, refresh_token(暗号化), location_id, connected_at)
google_reviews(id, business_id, google_review_id, rating, comment, author, posted_at, reply, fetched_at)
google_snapshots(business_id, total_count, average_rating, taken_at)   # 推移用
```

## 5. 表示（ダッシュボード追加）

- 「Google上の口コミ」カード：総件数・平均★・前回比
- 推移：週次/月次の件数・平均★の折れ線
- ツールの「Google誘導数」との並列表示（誘導→実投稿の歩留まり）

## 6. リスク・留意

- **審査が通らない/時間がかかる**可能性 → 事業計画をこれに依存させない
- OAuth検証・プライバシーポリシー整備が必要 → 個人開発には負担
- 規約遵守：取得データの表示は自店分のみ。**他店データのスクレイピングはしない**（Non-Goal）

## 7. 段階プラン（おすすめ順）

| Step | 内容 | 依存 | いつ |
|---|---|---|---|
| **Step 0（推奨・即可）** | ダッシュボードに **Google口コミ数・平均★を手動入力**する欄を追加。オーナーが時々記録し推移を見る | なし（0開発依存・テスト可） | 今すぐ |
| Step 1 | Google CloudでAPI利用申請・OAuthクライアント準備 | Google審査 | 検証と並行 |
| Step 2 | OAuth連携＋トークン保存、1店で取得疎通 | Step1承認 | 承認後 |
| Step 3 | cron定期取得＋ダッシュボード表示・推移 | Step2 | 〃 |
| Step 4 | OAuthアプリ検証対応で複数店に展開 | 検証通過 | 拡大期 |

> **Step 0 を先に入れておくと、API連携が整うまでの“表示の置き場”になり、その枠を後でAPIが自動で埋める**形にできる（無駄がない）。

## 8. この環境での制約

実際のGoogle API・OAuthは本物のGoogleアカウントと承認済みプロジェクトが必要で、**この開発環境では疎通テスト不可**。したがってStep2以降は本番ドメイン取得・申請後に実機で進める。
